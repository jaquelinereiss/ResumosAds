Engenharia de Requisitos

A engenharia de requisitos trata de descobrir, documentar e manter o que o sistema deve fazer e as restrições sob as quais deve operar. Requisitos bem-definidos são fundamentais para sucesso do projeto.

Fases

  1. Elicitação: entrevistas, workshops, observação, protótipos e análise de documentos para extrair necessidades dos stakeholders.
  2. Especificação: transformar necessidades em requisitos claros (funcionais e não funcionais). Ferramentas: user stories, casos de uso, requisitos formais.
  3. Validação: garantir que os requisitos representam a necessidade real (revisões, protótipos, aceitação do cliente).
  4. Gerenciamento: versionamento de requisitos, rastreabilidade (traceability) e controle de mudanças.

Tipos de requisitos

  • Funcional: comportamento, funcionalidades e regras de negócio.
  • Não funcional: desempenho, segurança, usabilidade, compatibilidade.
  • Requisitos de domínio: restrições específicas do setor (ex.: regulatórias).

Boas práticas

  • Usar linguagem clara e evitar ambiguidade.
  • Manter rastreabilidade dos requisitos até casos de teste.
  • Priorizar requisitos (MoSCoW: Must, Should, Could, Won't).
  • Prototipar para reduzir incertezas.
